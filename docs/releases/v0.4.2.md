# v0.4.2 Release Notes

Release date: May 22, 2026

## Highlights

- Closed the remaining cache-hash under-keying gaps found while auditing the
  `Cube.centered` fix from v0.4.1. Several inputs that affect produced geometry
  did not enter the content hash, so a hash-keyed cache could serve a
  stale/incorrect mesh.

## Bug Fixes

- **`weighted()` dropped the `WeightFunction`.** The cache hash for `weighted`
  captured only the receiver CSG, never the weight function, so different
  weights collided. The function is now hashed; the built-in modifiers
  (`XModifier`/`YModifier`/`ZModifier`/`UnityModifier`) are hashed by type and
  `centered` flag.
- **`Polygon` was hashed by identity.** Polygons reaching the hasher (via
  `Extrude.combine` and `CSG.fromPolygons`) fell back to identity `hashCode()`,
  which is non-deterministic across runs and collision-prone. They are now
  hashed by vertex content (position, normal, weight).
- **`Polyhedron` point/face structure could collide.** Points and face indices
  were flattened without length framing, so different groupings could hash
  alike. They are now length-prefixed.

## API Changes

- `XModifier.centered` / `YModifier.centered` / `ZModifier.centered` are now
  public read-only properties (previously private).

## Hardening

- The content hasher's fallback branch now fails loud (throws) instead of
  silently using `hashCode()`, so any future un-encoded type is caught at the
  source rather than producing a silent collision.
- Hashing a custom (non-built-in) `WeightFunction` now throws with guidance to
  disable caching via `csg(allowCaching = false)`, rather than risk serving a
  wrong cached result.

## Upgrade Notes

- Content hashes change for any model using `weighted`, `Polyhedron`,
  `Polygon`/`fromPolygons`, or the `remesh` flag. Existing cache entries become
  cold and recompute correctly on the next build — no manual cache clear needed.
