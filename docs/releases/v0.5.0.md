# v0.5.0 Release Notes

Release date: July 29, 2026

## Highlights

- **First KCSG release with breaking changes** — hence the minor bump rather
  than a patch. One public symbol is removed and one method's semantics change.
  See [Breaking Changes](#breaking-changes) before upgrading.
- Fixes two long-standing export/diagnostic defects inherited from upstream
  JCSG: exported OBJ files never loaded their material library, and a stray
  debug `print()` wrote to consumer stdout.
- The `csgs` CLI finally reports KCSG diagnostics instead of silently
  discarding every parse error and geometry warning.

## Breaking Changes

- **`Edge.Companion.polygons(List<Edge>, Plane)` removed.** It was a
  semantically identical duplicate of
  `Edge.Companion.toPolygons(List<Edge>, Plane)` — inherited from upstream
  JCSG's leftover `_toPolygons`, which the Kotlin conversion renamed into a
  legitimate-looking public name. `toPolygons` is the single entry point and is
  unchanged. This is **binary- and source-breaking**: callers of `polygons`
  switch to `toPolygons` (same parameters, same return type, same behavior).
  Both of `kcsg`'s ABI dumps (`kcsg/api/kcsg.api` and `kcsg/api/kcsg.klib.api`)
  lose the entry. (#30, PR #34)

- **`CSG.color(...)` now mutates the receiver.** It installs the color on the
  receiver — including every polygon's `PropertyStorage` — and returns `this`,
  instead of returning a colored copy while writing the color where nothing
  read it. **The signatures are unchanged, so the ABI is unchanged and
  `apiCheck` does not flag this**, which is exactly why it is called out here.
  Consequences:
  - Coloring the result of `union` / `difference` / `intersect` / `hull` now
    actually takes effect. Previously it silently no-op'd, because the color
    landed on a discarded copy.
  - Chained `color()` calls are last-wins rather than dropped.
  - Coloring a union collapses its per-primitive materials to the one color;
    color the primitives before combining if you want them preserved.
  - Use `csg.copy().color(...)` for the previous non-mutating form.

  (#28, PR #36)

## Bug Fixes

- **Exported OBJ files now load their material library.** `CSG.toObj()` wrote
  `mtllib <name>` with no terminating newline, so the following `# Group`
  comment ran onto the same line and the directive parsed as a filename of
  `<name># Group`. No OBJ/MTL pair exported by KCSG resolved its `.mtl`, so all
  material and color information was lost on import. The directive is now
  newline-terminated. This defect is inherited from upstream JCSG and remains
  unfixed there. `toObjString()` is unaffected — it writes a single file with no
  companion `.mtl` and deliberately emits no `mtllib` directive. (#29, PR #33)

- **Removed a stray `print()` from the edge boundary walk.** The private
  `Edge.Companion.boundaryPaths` wrote `edge: ...` lines directly to the
  consumer's stdout, reachable from the public `Edge.boundaryPolygons`. For a
  CLI or a host that writes its own data to stdout, this corrupted the output
  stream. It was a leftover the v0.3.0 `Logger` migration missed; the adjacent
  `logger` calls already trace the same walk. (#31, PR #34)

## CLI (`csgs`)

- **KCSG diagnostics now reach the user.** `Logger.setLogger` was never called
  by the CLI, so `Logger.Companion.log` no-opped and every core diagnostic — STL
  write failures, `Normal is zero!`, the optimization fallback warning, script
  parse errors — was silently discarded; a script producing a degenerate mesh
  exited 0 with nothing on stderr. The CLI now installs a `Logger` delegate at
  the top of `run()`. Warnings and errors are emitted unconditionally (a
  silently eaten failure is a bug, not a verbosity preference); informational
  and lower levels require the new `-v` / `--verbose` flag. Everything goes to
  stderr, keeping the CLI's own stdout output clean.

- **SLF4J removed.** It had been vestigial since v0.3.0, when the `Logger`
  abstraction replaced it. The version-catalog entries, the `:csgs` and
  `:samples` dependencies, and the leftover `SimpleLogger` log-level property in
  `Csgs.run()` are gone. (#32, PR #35)

## Maintenance

- PR CI (`library-quality`) now builds and tests `:csgs` and `:samples`, which
  it never did before — only `:kcsg` and `:kcsg-dsl` were covered, so a change
  that broke the CLI or the samples could go green. (#37, PR #38)

## Upgrade Notes

- **ABI:** unlike v0.4.5 (which was ABI-identical to v0.4.4), this release
  removes a symbol. The `kcsg` JVM `.api` and `.klib.api` dumps both drop
  `Edge.Companion.polygons`; nothing else in either dump changed, and the
  `kcsg-dsl` dumps are unchanged.
- **Source changes required only if you call `Edge.Companion.polygons`** —
  rename the call to `Edge.Companion.toPolygons`. Everything else compiles
  unchanged.
- **Review your `color()` calls.** Code that relied on `color()` returning a
  copy now mutates its receiver; code that colored a boolean result and saw no
  effect will now see the color applied. Substitute `csg.copy().color(...)`
  where the non-mutating behavior mattered.
- Hosts that export OBJ (e.g. Konstructor) should upgrade to pick up the
  `mtllib` fix — previously exported `.obj` files need re-exporting to reference
  their `.mtl`.
- CLI users who want informational output from KCSG should pass `-v` /
  `--verbose`; warnings and errors now appear on stderr with no flag.
