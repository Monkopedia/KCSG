# v0.4.3 Release Notes

Release date: June 9, 2026

## Highlights

- Cache-correctness fixes for hosts that cache intermediate CSGs (e.g. Konstructor),
  plus a new opt-in hook for invalidating imported-STL cache entries.

## Bug Fixes

- **ASCII STL round-trip now preserves full precision.** `STL.file` / `STL.from`
  parse ASCII STL coordinates as `Double` instead of `Float`. ASCII STL is written
  with full double precision, so the prior float32 parse truncated each coordinate
  to ~7 significant digits; when a cached intermediate CSG was reloaded from STL and
  fed into a further boolean operation, that error could change the result versus a
  fresh compute (the disk cache was not transparent). Binary STL remains float32
  (inherent to the format).

## API Changes

- **`KcsgHost.stlVersion(stlName): String`** (default `""`) — an opaque version token
  the host returns for a named STL, folded into the cache key of an `stl()` property.
  A host that returns e.g. the source STL's modification time now invalidates cached
  results when an imported STL changes. The default `""` preserves prior name-only
  keying, so existing host implementations are unaffected (non-breaking addition).

## Tooling & Docs

- Added `binary-compatibility-validator` (BCV) as a mechanical public-ABI gate for
  `kcsg` and `kcsg-dsl` (JVM `.api` + multiplatform `.klib.api`), complementing the
  existing `docs/public-api-checklist.md`. CI runs `apiCheck`.
- Added a Kodee sample (`kodee.csgs`) and a rendered README hero. Kodee is licensed
  CC BY 4.0 (JetBrains); see `THIRDPARTY-LICENSE.txt`.

## Upgrade Notes

- No source changes required. Hosts that implement caching may optionally override
  `KcsgHost.stlVersion` to get correct invalidation of imported-STL cache entries.
